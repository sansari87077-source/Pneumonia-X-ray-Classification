# DL-005 — Pneumonia X-Ray Classification Demo

**Domain:** Medical Imaging / Computer Vision  
**Interface:** Streamlit  
**Purpose:** Educational demonstration only. This is **not a medical diagnostic tool**.

## Project overview
Train a transfer-learning image classifier on a documented public, labeled chest X-ray dataset. The app displays a Normal-like or Pneumonia-like class and raw model scores. The training pipeline reports class balance, sensitivity, specificity, precision, recall, F1, ROC-AUC, a confusion matrix, and false-negative examples for inspection.

## Important limitations
This prototype is not clinically validated and must never be used for diagnosis, treatment, triage, or to rule out pneumonia. Model scores are not calibrated clinical probabilities. Performance can be misleading because of dataset artifacts, class imbalance, image-source differences, label noise, and limited population coverage.

## Dataset and documentation
A commonly used educational option is the **Chest X-Ray Images (Pneumonia)** dataset associated with Kermany et al. (2018), available from [Mendeley Data](https://data.mendeley.com/datasets/rscbjbr9sj/2) and mirrored on [Kaggle](https://www.kaggle.com/datasets/paultimothymooney/chest-xray-pneumonia). It contains pediatric chest X-rays from children aged approximately 1–5 years at Guangzhou Women and Children’s Medical Center. Review the source page, paper, and license/terms before use and cite them in your submission. Do not assume all mirrors have identical metadata or terms.

**Split safety:** Use the source's separate train/validation/test partitions where available and preserve patient-level separation. If patient IDs are available, verify no patient appears in more than one split. Do not randomly split individual images across sets when a patient has multiple images. If patient identifiers are missing or cannot be verified, state this as a limitation rather than claiming patient-level separation. The original commonly used folder structure has a very small validation split; consider creating a larger validation set from the training partition only after checking patient IDs and preserving the original test set untouched.

Arrange the data into exactly these folders:
```text
data/chest_xray/
├── train/
│   ├── NORMAL/
│   └── PNEUMONIA/
├── val/
│   ├── NORMAL/
│   └── PNEUMONIA/
└── test/
    ├── NORMAL/
    └── PNEUMONIA/
```
Place only normal images in `NORMAL` and pneumonia-labeled images in `PNEUMONIA`. Do not include extra class folders.

## Windows setup (Python 3.10 or 3.11 recommended)
Open PowerShell in the extracted project directory.

### 1. Virtual environment
```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```
If PowerShell activation is blocked, use Command Prompt:
```bat
.venv\Scripts\activate.bat
```

### 2. Install packages
```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```
TensorFlow compatibility depends on Python version and operating system. If installation fails, use a currently supported Python version from TensorFlow's installation documentation.

### 3. Train transfer-learning model
Make sure the dataset folders above are ready, then run:
```powershell
python train.py --data_dir data/chest_xray --epochs 8
```
The first run may download MobileNetV2 ImageNet weights, so internet access may be needed. The trained model is saved to `models/pneumonia_mobilenetv2.keras`. This ZIP does **not** contain trained weights: you must train it locally.

Optional fine-tuning after the frozen-feature training stage:
```powershell
python train.py --data_dir data/chest_xray --epochs 8 --fine_tune_epochs 3
```
This runs the full training pipeline again and fine-tunes the last layers at a low learning rate. Training time varies by hardware.

### 4. Inspect reports
After training, review:
- `reports/metrics.json` — test metrics including sensitivity and specificity
- `reports/classification_report.txt` — per-class precision/recall/F1
- `reports/confusion_matrix.csv` — TN, FP, FN, TP layout
- `reports/class_balance.json` — class counts per split
- `reports/false_negatives.csv` — paths of pneumonia cases predicted as normal; inspect these images carefully

The script uses the held-out `test/` folder only for final evaluation. Do not tune the model repeatedly against the test results. Metrics will be generated by your own training run; no results are pre-claimed.

### 5. Launch Streamlit
```powershell
streamlit run app.py
```
Open the local URL printed by Streamlit, usually `http://localhost:8501`.

## Evaluation definitions
Pneumonia is the positive class:
- **Sensitivity (recall for pneumonia)** = TP / (TP + FN)
- **Specificity** = TN / (TN + FP)
- **Precision** = TP / (TP + FP)
- **False negative (FN)** = an image labeled pneumonia but predicted normal.

Always report class counts beside metrics. A high accuracy alone can hide poor performance on a minority class.

## Troubleshooting
- **Model not found:** train first and check `models/pneumonia_mobilenetv2.keras`.
- **Dataset folders missing:** check spelling/capitalization and the `train`, `val`, and `test` folders.
- **Out of memory:** lower `BATCH_SIZE` in `train.py` from 16 to 8.
- **Very high scores:** do not assume success. Check data leakage, duplicate images, class imbalance, source artifacts, patient overlap, and false negatives.
